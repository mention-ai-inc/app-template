## UI copy earns its place or gets cut

Every user-visible string must state a fact or an action the user needs on that screen, at that moment. Anything else is cut, and "nothing" is a valid amount of copy. A bare heading beats a heading with a subtitle that adds nothing.

Cut a sentence when any of these is true:

- **Another element already says it.** A count in a tab badge is not repeated as a chip next to the title. A description does not restate its own title or its button's label ("Your note is waiting to be summarized" needs no "run it to get a summary" next to a **Summarize** button). A placeholder does not repeat the instruction above the input. Check the whole screen, including persistent chrome like tabs, before adding a number or state anywhere else.
- **It explains the mechanic instead of the moment.** Why summaries exist, what the retention window is for, how the pipeline decides what to do next belongs in product documentation, once. UI chrome shown on every visit never carries philosophy.
- **It narrates the obvious.** "It will appear here when it's done", "Replies stay in this thread", "Entries below open once they are ready". If the interface already behaves that way visibly, the sentence is noise.
- **It repeats across surfaces.** The same explanatory sentence must not appear on two screens. If you feel the need to say it twice, it belongs in the documentation, not in either screen.

What stays: state the user cannot see ("Being summarized", "Nothing was lost", "This page updates on its own"), who fixes what ("An owner can run it again"), the task itself in a form, and numbers with their units. One short sentence each, plain words users already know, no invented names.

When in doubt, delete the sentence and look at the screen. If nothing is missing, it was filler.
